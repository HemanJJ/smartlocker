# 規格：運動商城（盤商＋kiosk 自取）— 藍圖 v1

> 2026-08-21 定案方向（與老闆聊完）：**先做「B2C 零售＋量價階梯顯示」，第三方商家入駐不碰。**
> 本文件是規劃，**寫 code 前先給老闆看過**。

---

## 一、商業模式定案

| 角色 | 內容 |
|------|------|
| 你 | **盤商**：跟供應商「談」出底價（進價），不一定要囤貨 |
| 商品 | 總倉概念：`inventory` 表就是總倉（帳上數量＋談的進價＋上/下架） |
| 客人 | 個人（零售）＋ 球隊/企業（團購批發，50/100 件） |
| 出貨 | **kiosk 自取**：貨到 → 放格口 → 取件碼通知 → 客人到店自取 |
| 獲利 | 價差（售價 − 談的進價）；量價階梯鼓勵大批 |

## 二、三流圖（錢/貨/資訊）

```
資訊流：供應商談價 → 你上架（動態上下架） → 客人看到階梯價
錢流  ：客人付款(Phase2 LINE Pay) → 你付供應商（轉單）→ 你賺價差
物流  ：供應商出貨到店 → 你放 kiosk 格口 → 客人取件碼自取
```

## 三、資料設計（Phase A 要加的表）

```
price_tiers（量價階梯，動態可編輯）
  id, sku, min_qty, discount_percent, created_at
  例：DEFI-球  → 滿 50 → 80%（8折）
              → 滿 100 → 70%（7折）
  （後台可增刪改，即時生效；不寫死）
```

`inventory` 現有欄位已涵蓋總倉：`cost_price`（談的進價）／`qty`（帳上數）／`status`（上/下架）／`venue_id`（分店）。

## 五、Phase B（之後，等有人下批發單再蓋）

- 商品卡可選數量（1~200 大數字）→ 自動套階梯算價 → 確認單
- 團購/批發單：`sale_orders` 擴充（數量、階梯折扣、應付）
- 轉單：供應商 LINE 窗口（`line_id` 已有）→ 一鍵把單傳給供應商
- 自取：貨到 → 入格 → 取件碼（沿用穿線取件機制）

## 七、大件商品規則（2026-08-21 老闆說明）

- 現況：球拍／球鞋／球袋是大件，**暫不進 kiosk 格口**（實體在櫃台/倉庫交貨）。
- 老闆已設計**大櫃**硬體：未來大件也能進無人店自取。
- **規則將移除**：大櫃做好後，大件商品改為可上架 kiosk／無人店取貨（此規則自動失效）。

## 八、自動補貨流程（2026-08-21 完成）

```
① 安全存量（後台人工可調，每項）── 計算基礎
② 缺貨偵測：庫存 ≤ 安全存量 ✅
③ 需求單：建議補貨量 = 安全×2 − 庫存 ✅（後台 📤配貨 → 需求單）
④ 一鍵轉配貨單（草稿，不動庫存）✅
⑤ 人工審核：核准/退回/改數量 ✅
⑥ 核准 → 庫存移動（總倉−、店家+）＋LINE 通知「完成配送」✅
```

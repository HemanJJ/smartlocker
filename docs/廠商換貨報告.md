# UPUS-SKB25 锁控板 RS-485 通信故障报告

**报告日期**：2026-08-10
**产品型号**：UPUS-SKB25（25 路锁控板，MCU 丝印 IAP15W4K61S4）
**故障现象**：板卡 RS-485 完全无响应，发送任何指令均无任何字节返回
**受测板卡**：25 路板 ×1（MCU 丝印 IAP15W4K61S4）、50 路板 ×1（七段显示器 + 按键设址版）
**诉求**：请协助厘清型号与对应协议文档、提供上位机测试软件；若协议相符仍不通，申请换货

---

## 一、故障描述

锁控板 RS-485 接口对所有指令均无响应。**不是数据错误、不是乱码、不是偶发丢包，
而是一个字节都收不到。**

板卡本身有电（电源指示灯常亮，RESET 按钮有作用），但 485 通信完全不工作。

---

## 二、已完成的排查（全部排除）

### 2.1 上位机侧 — 已排除

在**两台完全不同的电脑、两种操作系统、两套独立编写的程序**上测试，行为完全一致：

| 平台 | 程序 | 结果 |
|---|---|---|
| Windows 7 | 自行开发的 C# 工具（.NET Framework） | 0 字节 |
| macOS | 自行开发的 Python 工具（pyserial） | 0 字节 |

两套程序发出的帧完全相同，均为 `55 A1 FF DF 00 D4`。

### 2.2 指令帧格式 — 已排除

发送帧与贵司《锁控板技术文档 V3.1》第 12 页 `DF广播寻址` 示例**逐字节一致**：

```
文档示例  发送：55 A1 FF DF 00 D4
          返回：55 A1 FF DF 01 01 D4
实际发送：      55 A1 FF DF 00 D4      ← 完全相同
实际返回：      （无，0 字节）
```

校验位按文档规定计算：`55 xor A1 xor FF xor DF xor 00 = D4`，正确。

### 2.3 波特率 — 已排除

9600 / 19200 / 38400 / 57600 / 115200，**五种全部无响应**。

### 2.4 地址码 — 已排除

除 `DF` 广播（地址 `FF`）外，另以点名方式测试：

- `DD 读MCU ID`：地址 **1 ~ 32 全部扫描**，无响应
- `D0 读系统配置`：地址 **1 ~ 8**，无响应

拨码开关 DP 五位**全部为 OFF**（按文档即地址码 1）。地址因素已完全排除。

### 2.5 USB-485 转换器 — 已排除（关键证据）

使用**两支不同的 USB-485 转换器互相对接自测**（A-A、B-B、GND-GND），
一支持续发送、一支纯接收：

```
接收端收到：55 A1 FF DF 00 D4
            55 A1 FF DF 00 D4
            55 A1 FF DF 00 D4
            ...（持续稳定接收）
```

**转换器、线材、软件、帧格式、波特率全部证实正常。**

### 2.6 接线位置 — 已排除

以下接法**全部测试过**，均为 0 字节：

| 接口 | 测试内容 |
|---|---|
| 绿色螺丝端子（丝印 `A` `B`，旁有 `120` 终端电阻焊盘） | A/B 正接与对调 |
| 白色 6P 级联座（第一个） | 红/黄/绿三线的 **6 种排列组合** 全试 |
| 白色 6P 级联座（第二个） | A/B 正接与对调 |

将板卡并入已验证正常的 485 总线后，**总线上的信号依然干净可读**
（另一支转换器仍能正常收到测试帧），说明板卡**没有把总线拉死或短路**，
但板卡自身完全不发送任何数据。

### 2.7 第二块板交叉验证 — 排除个例故障

另取同厂商不同型号的 50 路锁控板，以相同方法测试：
**行为与 25 路板完全一致，所有参数组合均 0 字节**。
两块独立板卡同时发送端故障的机率极低。

### 2.8 总线专职监听 — 板卡从未发送

以一支转换器专职监听、另一支专职发送，全程只收到我方送出的帧，
**板卡从未发送过任何一个字节**。若板卡以其他波特率回话，监听器会收到乱码；
但实际收到的是**绝对的零**。

### 2.9 实体板卡与《锁控板技术文档 V3.1》不符

- 文档为**蓝色 PCB**，实物为**黑色**
- 实物有 `Bluetooth module` / `Ethernet module` 空焊区，文档无
- 25 路板 TTL 为 `TTL IO` 2×2 焊盘，文档为 `5V Rx Tx Gnd` 一排
- **50 路板根本不在该文档内**（文档仅 SKB18 / SKB25 / SKB36）

## 三、万用表实测数据（决定性证据）

板卡通电（电源指示灯亮）、所有外部接线拔除、空闲状态下，
在**绿色螺丝端子**上实测（万用表 DC 20V 档）：

| 测量点 | 实测值 | 正常应为 |
|---|---|---|
| `−` → `+`（电源） | **15 V** | ✅ 电源已到达端子 |
| `−` → `A` | **0.18 V** | ❌ 应约 2~3 V |
| `−` → `B` | **0.18 V** | ❌ 应约 2~3 V |
| `B` → `A`（差分） | **0.00 V** | ❌ 应有明确偏置电位差 |

**结论：电源已正常送达端子，但 RS-485 收发芯片的 A / B 两脚
既无偏置电位、也无差分电压，处于完全未被驱动的状态。**

正常工作的 RS-485 收发器即使在空闲不发送时，A / B 也应被偏置电阻
拉至明确电位。本板卡两脚均贴近地电位、差分为 0，
表明**收发芯片未工作**（未供电、损坏，或与 MCU 之间的连接异常）。

## 四、结论

| 环节 | 状态 |
|---|---|
| 上位机软件 | ✅ 正常（两平台交叉验证） |
| 指令帧格式 | ✅ 正常（与贵司文档逐字节一致） |
| 波特率 | ✅ 已排除（5 种全试） |
| 地址码 | ✅ 已排除（广播 + 40 个点名地址） |
| USB-485 转换器 | ✅ 正常（两支对接自测通过） |
| 接线与接口 | ✅ 已排除（3 个接口、多种组合全试） |
| 板卡供电 | ✅ 正常（15V 已到端子，电源灯亮，RESET 有效） |
| **板卡 RS-485 收发功能** | ❌ 无响应（两块板一致） |
| **实体板卡 vs V3.1 文档** | ❌ **不符**（见 2.9） |

单板孤立故障已被第二块板交叉验证（2.7）排除；结合实体板卡与文档不符（2.9），
更可能是**我方持有的协议文档与实际出货板卡不对应**——
板卡收到无法解读的协议时完全静默，恰是正常板卡的行为。
